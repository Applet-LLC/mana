# キーボードレイアウト設定ツール まな

Windows 11 で、接続中のキーボードがどのハードウェア配列（Type / Subtype）として認識されているかを確認し、変更するツールです。変更はキーボード 1 台ごと、または PC 全体（`i8042prt`）に対して行えます。表示上のバージョンは 1.00 です。

たとえば、次のような場面で使えます。

- 日本語配列（JIS）のノート PC に英語配列（US）の USB キーボードをつないだら、記号の位置がずれる
- 英語配列のキーボードを、PC 全体で英語配列として認識させたい
- キーボードごとの特徴や設定内容を、メモや写真で残しておきたい

## 必要な環境

- 64 ビット版 Windows 11（ビルド 22000 以降）
- [.NET Desktop Runtime 9](https://dotnet.microsoft.com/ja-jp/download/dotnet/9.0)（x64）

  アプリはランタイムを同梱しない形式（フレームワーク依存）で配布しています。PC に **.NET Desktop Runtime 9**（x64）が必要です。ASP.NET Core Runtime や SDK では代わりになりません。入っていない場合は、上のリンクからインストールしてください。

  起動時に「.NET をインストールしてください」と表示されるのに、.NET のインストーラーでは「既にインストール済み」となる場合は、ランタイムの不足ではなく、配布物の不整合が原因のことがあります。最新の MSI で入れ直してください。

## インストール

配布フォルダの `Install-mana.exe` を実行し、画面で日本語または English を選んでインストールします。選んだ言語に応じて、次の MSI が使われます。

| 言語 | MSI |
|---|---|
| 日本語 | `manaSetup-1.00-ja-JP.msi` |
| English | `manaSetup-1.00-en-US.msi` |

`Install-mana.exe` と同じフォルダに、選んだ言語の MSI を置いておく必要があります。

- インストール先: `C:\Program Files\applet\mana`
- スタートメニュー: **Applet** グループに「キーボードレイアウト設定ツール まな」が登録されます

スタートメニューの一覧に **Applet** グループが表示されないことがあります。見当たらないときは、スタートメニューで「まな」または「mana」と検索してください。

## 使い方

### 基本の流れ

1. スタートメニューから**通常の権限で**起動します（「[起動時の注意](#起動時の注意)」を参照）。
2. 接続中のキーボードが一覧に表示されます。各キーボードの現在の配列と、その配列がどこで決まっているか（デバイス／グローバル／自動検出）を確認できます。
3. 設定を変更するときは、アプリ内の「**管理者として再起動**」を押します。レジストリ（HKLM）への書き込みには管理者権限が必要です。
4. デバイスごとの設定、またはグローバル設定を保存します。
5. 変更を反映させます。USB キーボードは抜き差し、内蔵キーボードやグローバル設定は Windows の再起動で反映されます。アプリを閉じるときに、そのまま再起動するかを選べます。

### デバイスごとの設定とグローバル設定

| | デバイスごとの設定 | グローバル設定 |
|---|---|---|
| 対象 | 一覧で選んだキーボード 1 台 | PC 全体 |
| 書き込み先 | `HKLM\SYSTEM\CurrentControlSet\Enum\<デバイスインスタンスパス>\Device Parameters` | `HKLM\SYSTEM\CurrentControlSet\Services\i8042prt\Parameters` |
| 値 | `KeyboardTypeOverride`、`KeyboardSubtypeOverride` | `OverrideKeyboardType`、`OverrideKeyboardSubtype`（プリセットによっては `OverrideKeyboardIdentifier`、`LayerDriver JPN` / `LayerDriver KOR` も） |
| 反映 | USB は抜き差し、内蔵は再起動 | 再起動 |

両方が設定されている場合、そのキーボードにはデバイスごとの設定が優先されます。

グローバル設定は、Windows の「設定」→「時刻と言語」→「言語と地域」→ 言語のオプションにある「**ハードウェア キーボードのレイアウト**」と同じものです。グローバル設定を保存すると「接続済みキーボード レイアウトを使用する」がオフになり、PC 全体の配列が固定されます。逆に、グローバル設定を削除すると「接続済みキーボード レイアウトを使用する」と同じ状態に戻ります。アプリには、この Windows の設定画面を開くボタンもあります。

### プリセット

デバイスごとの設定とグローバル設定のどちらでも、「国・配列プリセット」から次のプリセットを選べます。「カスタム」を選ぶと、Type と Subtype を数値で直接入力できます。「一緒に書き込まれる値」は、グローバル設定にプリセットを適用したときだけ書き込まれます。デバイスごとの設定に書き込まれるのは Type と Subtype だけです。

| プリセット | Type | Subtype | 一緒に書き込まれる値 |
|---|---|---|---|
| 拡張 101/102（US） | 4 | 0 | なし（`OverrideKeyboardIdentifier`、`LayerDriver JPN` / `KOR` は削除） |
| 日本語（JIS） | 7 | 2 | `OverrideKeyboardIdentifier` = `PCAT_106KEY`、`LayerDriver JPN` = `kbd106.dll` |
| 韓国語 101 Type 1 | 8 | 3 | `OverrideKeyboardIdentifier` = `STANDARD`、`LayerDriver KOR` = `kbd101a.dll` |
| 韓国語 101 Type 3 | 8 | 5 | `OverrideKeyboardIdentifier` = `STANDARD`、`LayerDriver KOR` = `kbd101c.dll` |
| カスタム | 任意 | 任意 | Type / Subtype を直接入力 |

どの設定もない場合、配列は「自動検出」と表示され、Windows がキーボードから判断します。

## 使用例

### 例 1: JIS 配列のノート PC に US 配列の USB キーボードをつなぐ

内蔵キーボードは日本語配列のまま、外付けキーボードだけを英語配列として認識させます。

1. まなを起動し、「管理者として再起動」を押します。
2. 画面上部に「事前準備が必要です」と表示されている場合は、グローバル設定が残っています。「**グローバル設定を削除**」を押してください（「事前準備済」と表示されていれば不要です）。
3. 一覧から外付けの USB キーボードを選びます。
4. 「デバイスごとのオーバーライド」の「国・配列プリセット」で「**拡張 101/102（US）**」を選び（Type `4`、Subtype `0` が入ります）、「**デバイス設定を適用**」を押します。
5. USB キーボードを抜き差しします。手順 2 でグローバル設定を削除した場合は、Windows も再起動してください。
6. 外付けキーボードの `@` や `[` などの記号が、キートップの刻印どおりに入力できることを確認します。

### 例 2: PC 全体を US 配列に固定する

デスクトップ PC で英語配列のキーボードだけを使う場合などです。

1. まなを起動し、「管理者として再起動」を押します。
2. 「グローバル設定 (i8042prt)」で「国・配列プリセット」に「**拡張 101/102（US）**」を選び、「**グローバルプリセット適用**」を押します。
3. 「接続済みキーボードレイアウトを無効にしますか？」と確認されたら「続行」を押します。
4. アプリを閉じるときに「今すぐ再起動」を選び、Windows を再起動します。

日本語配列に固定したい場合は、手順 2 で「**日本語（JIS）**」を選びます。

### 例 3: 設定を元に戻す

- **特定のキーボードだけ戻す**: 一覧でキーボードを選び、「**デバイス設定を削除**」を押してから、抜き差しまたは再起動します。
- **PC 全体の固定をやめる**: 「**グローバル設定を削除**」を押し、Windows を再起動します。「接続済みキーボード レイアウトを使用する」と同じ状態になります。

どちらも削除すると、配列は「自動検出」に戻ります。

### 例 4: キーボードのメモを残す

1. 一覧でキーボード名をクリックすると、詳細ウィンドウが開きます。
2. ドライバスタックの確認、メモ（Markdown）の記入、画像の確認ができます。メモには、たとえば次のように書けます。

   ```markdown
   ## 会社支給の US キーボード
   - 購入: 2026-04
   - 設定: Type 4 / Subtype 0（デバイスごと）
   - [ ] キーキャップ交換予定
   ```

3. 「フォルダを開く」でキーボードごとのフォルダが開きます。ここに JPG または PNG の画像を置くと、一覧のサムネイルと詳細ウィンドウに表示されます。

メモで使える Markdown 記法は [docs/MEMO-MARKDOWN.md](docs/MEMO-MARKDOWN.md) にまとめています。今は接続していないキーボードのメモは、「**過去のキーボード一覧**」から開けます（ドライバスタックは表示されません）。

## その他の機能

- **一覧から隠す**: 各行の「非表示にする」チェックボックスで、使わないキーボード（仮想デバイスなど）を一覧から隠せます。「設定」の「非表示のキーボードも一覧に表示する」で再び表示できます。
- **レジストリを直接確認する**: 「デバイスのレジストリを開く」「グローバルのレジストリを開く」で、該当するキーをレジストリ エディターで開けます。
- **ロケール別レイアウトファイル**: 日本語（`00000411`）、英語（`00000409`）、韓国語（`00000412`）について、`HKLM\SYSTEM\CurrentControlSet\Control\Keyboard Layouts\<ロケール>` の `Layout File`（例: `KBDJPN.DLL`、`kbd106.dll`、`KBDUS.DLL`）を変更できます。Windows の標準の動作を変える上級者向けの設定です。変更する前に、元の値を控えておいてください。
- **表示言語**: 「設定」で日本語と English を切り替えられます。

## データの保存先

| 内容 | 保存先 |
|---|---|
| メモ・画像・接続履歴 | `%LocalAppData%\mana\db\<キーボードごとのフォルダ>`（「設定」で保存先を変更できます） |
| 表示言語・ウィンドウ位置・非表示にしたキーボード | `%LocalAppData%\mana` |
| 起動失敗時のログ | `%LocalAppData%\mana\startup-crash.log` |

キーボードごとのフォルダ名は、デバイスインスタンスパスの `\` を `_` に置き換えたものです。たとえば `HID\VID_046D&PID_C31C&MI_00\7&1A2B3C4D&0&0000` のメモは、`%LocalAppData%\mana\db\HID_VID_046D&PID_C31C&MI_00_7&1A2B3C4D&0&0000\memo.md` に保存されます。

アプリをアンインストールしても、これらのデータは削除されません。不要な場合は手動で削除してください。

## 起動時の注意

**実行ファイルを右クリックして「管理者として実行」しないでください。** 最初から管理者として起動すると、WinUI 3 が `Microsoft.UI.Xaml.dll` で異常終了することがあります。設定の確認は通常の権限で行い、書き込むときだけアプリ内の「管理者として再起動」を使ってください。

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| スタートメニューに見当たらない | スタートメニューで「まな」または「mana」と検索してください。 |
| 起動しない、すぐに終了する | 「管理者として実行」で起動していないか確認してください。原因は `%LocalAppData%\mana\startup-crash.log` に記録されます。 |
| 「.NET をインストールしてください」と表示される | .NET Desktop Runtime 9（x64）をインストールしてください。インストール済みなのに表示される場合は、最新の MSI で入れ直してください。 |
| ボタンを押しても保存できない | 管理者権限が必要です。「管理者として再起動」を押してください。 |
| 設定したのに配列が変わらない | USB キーボードは抜き差し、内蔵キーボードやグローバル設定は Windows の再起動が必要です。デバイスごとの設定が効かないときは、グローバル設定が残っていないか（画面上部が「事前準備が必要です」になっていないか）も確認してください。 |
| 記号の位置がおかしくなった | 「[例 3: 設定を元に戻す](#例-3-設定を元に戻す)」の手順で、設定を削除して再起動してください。 |

## 開発者向け

Visual Studio 2022 で、ソリューションを一括ビルドできます（アプリ、言語選択ランチャー、インストーラー、EV 署名まで）。インストーラープロジェクト `manaSetup`（WiX v5）のビルドには [HeatWave for Visual Studio 2022](https://marketplace.visualstudio.com/items?itemName=FireGiant.FireGiantHeatWaveDev17) が必要です。

- 成果物の出力先: `installer\dist`
- バージョン: `mana.csproj` 内の内部バージョンは `1.0.0`、配布ファイル名のバージョンは `1.00`
- 署名: EV 証明書（Subject: Applet LLC）が見つからない場合は、署名を省略してビルドを続けます

NuGet パッケージを追加・更新したときは、[THIRD-PARTY-NOTICES.txt](THIRD-PARTY-NOTICES.txt) も更新してください。

設計の詳細は [ARCHITECTURE.md](ARCHITECTURE.md) を参照してください。
